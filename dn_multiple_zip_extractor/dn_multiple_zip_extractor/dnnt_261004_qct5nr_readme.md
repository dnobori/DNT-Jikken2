## 2. ビルド

### 2.1 前提

Windows 側に .NET Framework の C# コンパイラが必要です。典型的なパスは `%WINDIR%\Microsoft.NET\Framework\v4.0.30319\csc.exe` です。フォルダ名が `v4.0.30319` でも、インプレース更新により実際のコンパイラや参照アセンブリが新しい 4.x のものである場合があります。厳密な .NET 4.0 API 検査には第 2.3 節を使用してください。

ソースは UTF-8 BOM 付きで格納しています。以下は **cmd.exe 用**のコマンドです。PowerShell の構文ではありません。ソースを置いたディレクトリへ移動して実行します。管理者権限は原則不要です。

### 2.2 Framework コンパイラを直接使用する

```bat
"%WINDIR%\Microsoft.NET\Framework\v4.0.30319\csc.exe" ^
  /nologo /target:winexe /platform:anycpu /langversion:4 /checked- /optimize+ /codepage:65001 ^
  /out:"dnnt_261004_qct5nr_split_zip_extract.exe" ^
  /reference:System.dll /reference:System.Core.dll /reference:System.Windows.Forms.dll ^
  "dnnt_261004_qct5nr_split_zip_extract.cs"
```

`/checked-` は暗号の剰余演算等の前提に合わせた指定です。外部ライブラリの参照はありません。EXE はこのソースだけから生成します。追加の `.csproj`、`.config`、マニフェスト、デザイナーファイルを必須としない構成です。

この方法で選択される標準アセンブリはインストール状態に依存します。これだけで旧 .NET 4.0 の API と完全に照合できたとは扱わないでください。

## 3. 起動と入力

生成した EXE を引数なしで起動すると、すべてのファイルを対象にした複数選択可能な「ファイルを開く」ダイアログを表示します。引数を使う場合は、各ファイルの完全修飾パスを指定します。

```bat
dnnt_261004_qct5nr_split_zip_extract.exe "C:\Archives\sample.zip.aa" "C:\Archives\sample.zip.ab"
```

相対パス、ドライブ相対パス、存在しない入力、異なる親ディレクトリにある入力は受け付けません。入力元がリンクやジャンクションの配下にあること自体は拒否しません。入力名の大文字・小文字、取得できる 8.3 長名、取得できるファイル ID を用いて重複を除去します。ファイル ID による重複除去は同一実体のハードリンクも対象とします。ファイル ID が取得できない場合は、同一 ID と推測して入力を捨てることはしません。

ファイル名に `zip` を含まない入力は除外リストとして表示して処理しません。対象が一つも残らない場合は終了します。対象はファイル名の `StringComparer.Ordinal` 順に処理するため、ASCII 名では ASCII コード順です。自然順ソートではなく、例えば `part10` と `part2` の並びに注意してください。足りない断片を自動検索して追加する処理はありません。

入力ファイルは読み取り専用かつ書き込み・削除共有なしで保持し、処理中の変更を防ぎます。そのため、他のアプリが排他利用している場合等は開始できません。

## 4. モード判定と ZIP 対応範囲

各入力単独での ZIP 構造検証と、全入力を名前順に仮想連結した ZIP の構造検証を行います。EOCD、ZIP64 EOCD / locator、中央ディレクトリ、すべてのローカルヘッダ、ファイル名、サイズ、flags、CRC メタデータ、data descriptor の有無・長さ・値、領域の連続性を照合します。CRC の実データとの比較、Deflate の検証、AES 認証は展開時に行います。

単独 ZIP 群として整合するなら個別複数 ZIP モード、全体の連続ストリームとして整合するなら巨大 ZIP 分割モードになります。一つの入力 ZIP は「個別複数 ZIP モード（単一 ZIP）」と表示します。両候補が成立する曖昧な複数入力、どちらも成立しない入力は選択せず、個別結果と連結結果を表示して終了します。

論理連結ストリームは 64 bit の位置を扱い、必要な入力ファイルの領域だけを読みます。**連結済み ZIP をディスクに作成しません。** 入力ファイル数・エントリ数に比例したメタデータはメモリに保持します。32 bit プロセスでは巨大なエントリ数によってメモリが不足する可能性があります。

対応する主な形式は次のとおりです。

| 項目 | 実装 |
| --- | --- |
| 圧縮方式 | Store (0)、Deflate (8) |
| ZIP サイズ | ZIP32、ZIP64。実装上の長さ上限は符号付き 64 bit |
| data descriptor | 32 bit / 64 bit、シグネチャあり / なし |
| 暗号 | ZipCrypto、WinZip AES AE-1 / AE-2、128 / 192 / 256 bit |
| 整合性 | 展開サイズ、CRC-32。AE-2 は CRC の代わりに必須の HMAC 認証を使用 |
| 名称 | UTF-8 flag、検証済み Info-ZIP Unicode Path、旧式コードページ |
| 日時 | DOS、NTFS extra、Extended Timestamp、旧 UNIX extra |

意図的に受け付けない、または限定対応となる形式があります。

- ZIP 自身のマルチディスク方式、SFX 実行形式、先頭・末尾の付加データ、未参照ローカルレコードや空隙、中央とローカルの矛盾した名前・メタデータは構造エラーです。通常の ZIP として他ソフトが許容しても、本実装は拒否する場合があります。
- Store / Deflate 以外、PKWARE strong encryption、暗号化中央ディレクトリ、patched data 等は対応しません。エントリの範囲を安全に解釈できる場合は個別警告、アーカイブ構造自体を解釈できない場合は判定段階で終了します。
- デジタル署名レコードは構造のみを確認し、署名者の真正性は検証しません。未知の extra field は長さを検査して読み飛ばします。認識した主要 extra field の重複は曖昧な情報として拒否します。

## 5. 日本語名とパスワード

### ファイル名

UTF-8 flag を優先し、対応する Unicode Path extra は元名 CRC と整合性を検査します。符号化情報がない場合、既定では日本語 Windows 用の CP932 として復号し、CP932 で不正なバイト列の場合は CP437 を試します。

文字コードの自動判定は完全にはできません。例えば CP932 としても有効な CP437 名や、UTF-8 flag のない UTF-8 名は、誤った見た目で解釈される場合があります。入力元の仕様に合わせて環境変数 `DNNT_ZIP_CODEPAGE` に `932`、`437`、`65001` 等を指定してください。

```bat
set DNNT_ZIP_CODEPAGE=65001
dnnt_261004_qct5nr_split_zip_extract.exe
```

CP932 の文字内に `0x5c` バイトがあるケースを避けるため、バイト列を文字列に復号してからパス区切りを扱います。ZIP 仕様の正式な区切りは `/` です。本実装では互換性のため `\` も区切りとして受け入れ、両方を Windows の `\` に正規化します。

### パスワード

EXE と同じディレクトリの `password_list.txt` を起動時に読みます。UTF-8、先頭 BOM 任意、1 行 1 候補です。空行と完全一致する重複行は除外します。前後の空白はパスワードの一部として保持します。このファイルは読み取りのみで、追加・更新しません。ファイルの読み取り専用属性は付いていても付いていなくても構いません。ファイルがなければ候補は空、存在して読み取りに失敗する場合はエラーで終了します。

既知候補は出力先への書き込みをせず、サイズ・Deflate・CRC または AES 認証まで実際に検証します。ZipCrypto のヘッダ 1 byte や AES の 2 byte verifier の一致だけでは成功としません。実装差に備え、パスワード文字列の UTF-8、設定コードページ、CP437、現在の ANSI / OEM の重複しないバイト表現も試します。

どの候補も成功しなければ入力を求めます。入力内容は画面へエコーしません。Enter だけの空パスワードも有効な候補です。成功した文字列をメモリ上の先頭へ追加します。大文字・小文字を区別する特殊入力 `ignore` は、その時点のエントリを省略し、以後は既知候補だけを試すモードへ移ります。暗号化されていないファイル、および既知候補で展開できるファイルは引き続き処理します。

`ignore` というパスワードを対話入力することはできません。同じ文字列が本当のパスワードの場合は、開始前に `password_list.txt` に登録してください。空パスワードは空行を無視する仕様のため、初回は対話入力で登録します。

不正なパスワードと暗号データの破損は区別できない場合があります。その場合も仕様どおり再入力または `ignore` の選択を求めます。既知パスワードの検証と実保存のため、暗号化ファイルは成功時でも基本的に圧縮データを 2 回読みます。不一致候補数とデータ量によって追加の時間・I/O がかかります。パスワードや一部の鍵配列は可能な範囲で消去しますが、.NET の不変 `string` や OS のページングを含むメモリ上の完全消去は保証しません。

## 6. 展開先と重複・上書き

「ファイル名を付けて保存」ダイアログで `_dummy.txt` を既定名にします。この架空ファイルは作成しません。入力名を変更しても、その親ディレクトリを展開先として使用します。標準 `SaveFileDialog` にファイル名編集だけを安全・簡単に禁止する設定がないため、ファイル名の変更は許可しています。上書き確認と新規ファイル作成確認は、このダイアログでは無効にしています。

ZIP 内の正規化後のファイルパスを、大文字・小文字を区別せず比較します。重複がある場合、`Y` は以後すべての重複を許可、`y` はその組だけ許可、`n` は中断です。許可した場合も、実際に展開するのは最初の一つだけです。順序はソート済み ZIP の順、その中ではローカルヘッダの出現順です。最初のエントリが後で失敗しても、重複する後続エントリを代わりに使うことはしません。

明示ディレクトリエントリの重複は同じディレクトリとしてまとめ、日時は最初の有効な明示情報を使用します。同じパスがファイルとディレクトリを兼ねる構造、ファイルを親ディレクトリとして必要とする構造は中断します。

事前の物理ファイル上書き確認は `y / n / a / q`、実行中に新たに検出した上書きは `Y / N / y / n / q` です。文字の大小は区別します。事前確認で記録した対象とファイル ID、サイズ、更新日時が変わった場合も、再確認の対象とします。ファイル ID が取得できず同一実体を確認できない環境では、再確認が増える場合があります。明示的な上書き省略と ZIP 内重複の後続省略は失敗に数えません。

展開されたデータは最終ファイルと同じディレクトリの一時ファイルに書き、展開サイズ・CRC・認証を検証してから、開いたハンドルを使って最終名へ改名します。既存ファイルを先に削除しません。一時ファイルは「ZIP を結合したファイル」ではなく、一つの内容ファイルの検証前出力です。検証失敗時は削除しますが、アプリや OS の強制終了、削除権限や共有サーバーの問題では一時ファイルが残る場合があります。

## 7. パスとリンクの安全性

安全性に関するエラーは個別ファイルの警告にはせず、全体を中断します。

絶対パス、ドライブ指定、UNC として始まる ZIP 名、`..` 要素、ADS を作る `:`、NUL 等の制御文字、Windows の禁止文字、予約デバイス名、リンク・特殊ファイル属性を拒否します。`./` と重複区切りを整理し、各要素末尾の空白・ドットを正規化して衝突を検査します。正規化で空になる名前等は拒否します。Unicode 正規化 NFC/NFD により名前を勝手に変更することはしません。

Unicode extra の採用名だけでなく、元バイト列を復号した旧式名とローカルヘッダ側の名にも危険パス検査を行います。中央の external attributes、ASi UNIX / UNIX extra 等から判別できる symlink、デバイス等の特殊オブジェクトも拒否します。

**安全側の追加制限があります。** `FOO~1.TXT` のように 8.3 短縮名に見える名前は、まだ存在しない出力の将来の短縮名まで含めた衝突を事前確定できないため、実際には普通の長い名前として意図されていた場合でも拒否します。既存の展開先ファイルが複数ハードリンクを持つ場合も、確認を通じて上書きするのではなく全体を中断します。これらは一般的な ZIP 展開ソフトより厳しい制約です。

ユーザーが選んだ展開先ルート自身、およびその指定パスの祖先にあるシンボリックリンク・ジャンクションは許容します。一方、展開先ルートから ZIP の相対パスをたどる途中にある reparse point は拒否します。対象ルートのパス要素、および書き出し中の子ディレクトリを、削除・書き込み共有なしのハンドルで保持します。最終要素も no-follow で検査し、検査済み一時ファイルのハンドルを使用して保存します。 属性専用ハンドルに共有制御を依存させないため、固定するディレクトリには `FILE_LIST_DIRECTORY` も要求します。実際の一覧取得はしませんが、書き込み・通過だけ許可され一覧権限がない保存先や祖先では、安全な固定に失敗する場合があります。

この制御は、Windows とファイルシステム / ネットワークサーバーが所定の共有モード、再解析ポイント、ファイル ID、ハンドル操作を正しく実装していることを前提とします。管理者・カーネル権限の攻撃者や悪意のあるサーバーに対する隔離を保証するものではありません。自作コードであることも無脆弱性の保証ではありません。

UNC とドライブ割り当てパスはそのまま使用し、`GetFinalPathNameByHandle` やネットワークドライブの UNC 化 API は使いません。入力の `GetLongPathNameW` は 8.3 名の長名化だけに使用し、リンク先のリアルパス化とは別です。

一部の NAS / ファイルシステムが必要な共有・ハンドル改名・ファイル ID 等を提供しない場合、安全でない代替処理へ切り替えずに失敗します。新規作成したディレクトリの ID が取得できず、後で同一実体を確認できない場合も中断対象です。UNC 対応は任意の NAS に対する動作保証ではありません。

通常の MAX_PATH 制限を使用します。ファイル等の完全パスは 260 文字未満、新規作成ディレクトリは 248 文字未満に制限します。制限を超える内容ファイルは個別警告です。拡張長・デバイス名前空間は使用しません。

## 8. 日時

通常の DOS 日時は ZIP の作成時のタイムゾーン情報を持たないため、実行環境のローカル時刻として解釈します。NTFS の FILETIME と UNIX 系の時刻は UTC として扱います。優先順位は NTFS extra、Extended Timestamp、旧 UNIX extra、DOS 日時の順です。同種の情報ではローカルヘッダ側を優先します。32 bit UNIX timestamp は符号付き値として解釈します。

内容ファイルの作成・更新・アクセス日時は、それぞれ有効な値がある場合に設定し、作成・アクセス日時が省略されている場合は更新日時で補います。新規ファイルでも上書きファイルでも同様です。有効な日時がない場合、OS が設定した値を維持し警告します。日時設定に失敗しても保存内容を破棄せず、警告として記録します。

本処理が新規作成したサブディレクトリだけに日時を設定します。明示された ZIP ディレクトリエントリの日時を優先し、それがなければ重複除去後の展開計画にある子孫ファイルの最も新しい更新日時を作成・更新・アクセス日時に使います。計画段階ですでに保存不能と判定したファイルは、この集計から除外します。後から選択される上書き省略、暗号化 ignore、実行中の失敗によって集計を再計算する設計ではありません。

作成直後に一度設定し、ファイル展開の終了後にも深いディレクトリから再設定します。途中中断時も可能な範囲で後処理を試みます。既存ディレクトリとユーザーが選択したルートの日時は明示設定しません。ただし、そのディレクトリ内のファイルを作成すれば OS 自身が既存ディレクトリの更新日時を変える場合があります。

## 9. エラー、終了、運用上の限界

一つの内容ファイルの CRC 不一致、Deflate 破損、保存不能、未対応圧縮、日時設定失敗などは警告に記録して次へ進みます。危険パス・リンク境界・ZIP の構造不整合、ユーザーの中断は全体を終了します。終了時には成功ファイル数とサイズ、警告、意図的な省略数、末尾が `\` の展開先パスを表示します。途中で全体中断した場合は例外内容を表示し、完了したかのような最終集計は表示しません。

成功または失敗の表示後、コンソールはキー入力待ちになります。対話的なデスクトップ用途を前提とし、無人・サービス実行用のモードはありません。Ctrl+C は可能な場所で中断要求として扱います。ダイアログや入力待ちの状態によっては、直ちに処理を離れないことがあります。

代表的な終了コードは以下です。

| 値 | 意味 |
| --- | --- |
| 0 | 警告なしで完了。承認済みの重複・上書き省略は成功扱い |
| 299 | 完了したが、個別ファイルまたは日時等に警告あり |
| 1223 | ユーザーによる取り消し・中断 |
| 5 | 安全性違反、またはアクセス拒否 |
| 2 / 3 | 入力等のファイル / ディレクトリが見つからない |
| 13 | ZIP の構造不正・形式不正 |
| 87 | 引数不正 |
| 50 | OS または機能が非対応 |
| その他 | 取得できた Win32 エラー、または一般失敗 31 等 |

警告件数は原因メッセージの数ではなく対象ファイル単位を基本とします。内容が保存されていても日時設定に失敗したファイルは警告対象です。ディレクトリの警告は別に表示します。

展開全体を一つのトランザクションとしてロールバックする処理はありません。中断前に確定したファイルや新規ディレクトリは残ります。ファイルを確定する処理も、突然の電源断に対する永続化まで保証するものではありません。

Deflate の距離、ハフマン木、最終ブロック、宣言サイズを超える出力、圧縮データ末尾の余剰等は検査します。ただし、ZIP に宣言されたサイズ自体が巨大であるケースに対する総出力容量・圧縮率・実行時間の独立した上限設定はありません。信頼できない ZIP は、空き容量を確保した専用の展開先で扱ってください。既存の重要データがある保存先では事前にバックアップを作成してください。

#### 6.2 原因の分類と ZIP 仕様との関係

今回は新しい暗号方式や圧縮方式の欠如ではない。サンプルは既存実装が対応する ZipCrypto と Deflate を使用していた。エラーはパスワードを試す前の構造判定で発生している。

PKWARE APPNOTE の bit 3 の書込み規定では、ローカル CRC と両サイズをゼロとし、後続 descriptor に確定値を置く説明がある。本サンプルの非ゼロ暫定 CRC を、仕様が任意値として明示的に許可していると説明することはできない。一方、読み取り実装が descriptor と中央の確定値を照合できる状況で、ローカル暫定値だけを理由に拒否する必要はない。本修正は、実際に流通する作成実装との読み取り互換性を改善するものと位置付けた。

この位置付けの裏付けとして、Info-ZIP 3.0 で無害な合成入力を暗号化し、出力をシークできないパイプへ接続して ZIP を生成した。単なる通常ファイルへのリダイレクトとは分けて検証している。

#### 6.3 「全断片の仮想連結」のエラーが併記された理由

`Detector` は二つの候補を検査するため、個別 ZIP 判定の失敗に加えて、全体を 1 ZIP とみなした候補の失敗も表示する。独立した ZIP 群を単純に連結すると、通常は 1 個の連続 ZIP の中央ディレクトリとして整合しない。したがって、この併記だけで欠落断片や順序違いが確定したわけではない。

指定サンプルは単独 ZIP として構造・内容を検証できた。R02 の対応規則ではこのサンプルを個別 ZIP として受理する。他の入力もすべて単独で有効なら、既存 `Detector` は個別複数 ZIP モードを選択する。今回取得したサンプル以外の 45 ファイルは提供されていないため、元の 46 ファイル全体を実行して確認したとは記録しない。

#### 8.3 本体単独を WinExe としてコンパイルする場合

以下は **Windows の cmd.exe 用**である。カレントディレクトリに R02 ソースを置き、実在する Framework コンパイラと参照アセンブリを用いる。C# 本体は標準アセンブリだけを参照し、`Lib.cs` はこの単独ビルドには含めない。

```bat
"%WINDIR%\Microsoft.NET\Framework\v4.0.30319\csc.exe" ^
  /nologo /target:winexe /platform:anycpu /langversion:4 /checked- /optimize+ /codepage:65001 ^
  /out:"dnnt_261004_qct5nr_split_zip_extract.exe" ^
  /reference:System.dll /reference:System.Core.dll /reference:System.Windows.Forms.dll ^
  "dnnt_261004_qct5nr_split_zip_extract_r02_261007_tfdxe5.cs"
```

厳密に Framework 4.0 の API を対象にする場合は、正規の v4.0 参照アセンブリを明示する。次の `REF4` は、その環境の実在パスへ合わせる。

```bat
set "REF4=C:\Program Files (x86)\Reference Assemblies\Microsoft\Framework\.NETFramework\v4.0"
"%WINDIR%\Microsoft.NET\Framework\v4.0.30319\csc.exe" ^
  /nologo /noconfig /nostdlib+ /target:winexe /platform:anycpu /langversion:4 /checked- /optimize+ /codepage:65001 ^
  /out:"dnnt_261004_qct5nr_split_zip_extract.exe" ^
  /reference:"%REF4%\mscorlib.dll" ^
  /reference:"%REF4%\System.dll" ^
  /reference:"%REF4%\System.Core.dll" ^
  /reference:"%REF4%\System.Windows.Forms.dll" ^
  "dnnt_261004_qct5nr_split_zip_extract_r02_261007_tfdxe5.cs"
```

`v4.0.30319` というコンパイラのフォルダ名だけで、参照先も厳密な .NET 4.0 になるとは限らない。上記コマンドを今回の Linux 環境で実行したわけではない。

Microsoft は Visual Studio 2022 以降について、Framework 4.0～4.5.1 を対象にした標準の IDE ビルドを非対応と案内している。したがって「VS 2026 の標準設定だけで公式にサポートされる Framework 4.0 ビルドを確認済み」とは記載できない。Framework の目標は勝手に 4.8 等へ変えず、既存の構成、旧バージョンの対応 IDE、または明示的な旧 Framework コンパイラの呼出しを使う。VS 2026 の外部ツール設定については、既存 README 第 2 節の方式を R02 ファイル名に合わせて利用できる。
